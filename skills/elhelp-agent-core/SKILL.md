# ElHelp Agent Core — يعمل بدون API

هذا الـ Skill هو عقل الـ Agent المحلي. **لا يحتاج OpenAI / Anthropic / أي API خارجي**.

## متى يُستخدم
- عندما يطلب المدير: "راجع التقارير"، "لخص يوم مهندس"، "حلل المسار"، "هل فيه مشاكل ميدانية؟"
- عندما يعمل الـ Agent تلقائياً كل ساعة أو عند حدث (زيارة جديدة، تقرير يومي جديد).

## كيف يعمل (بدون LLM)
1. **تحميل الـ Skills**: يقرأ كل ملف `skills/*/SKILL.md` من القرص (frontmatter + تعليمات).
2. **اختيار المهمة**: يحوّل طلب المستخدم إلى واحدة من المهام المحددة مسبقاً:
   - `review-daily-reports` — مراجعة التقارير المعلقة
   - `summarize-day` — ملخص يوم مهندس/فريق
   - `analyze-route` — تحليل مسار GPS وكشف القفزات
   - `field-alerts` — تنبيهات ميدانية ذكية
3. **تنفيذ بقواعد صلبة**: كل مهمة لها كود TypeScript محدد في `server/src/agent/tasks/` — لا تخمين، لا هلوسة.
4. **إخراج عربي RTL**: كل النتائج بالعربية، جاهزة للعرض في لوحة المدير أو كـ JSON للـ API.

## القواعد الذهبية
- **لا يتصل بالإنترنت أبداً** — كل الحسابات محلية (SQLite + dayBounds + haversine).
- **لا يبدأ تتبع ولا يعدّل بيانات** — يقرأ فقط، القرار للمدير.
- **يحترم الخصوصية**: لا يكشف مواقع خارج الوردية، ويحترم `is_demo` و `active`.
- **Deterministic**: نفس المدخلات = نفس المخرجات، قابل للاختبار.

## API المحلي
```
GET  /api/agent/skills              → قائمة الـ Skills المحملة
POST /api/agent/run  { task, ... }  → تنفيذ مهمة وإرجاع النتيجة
GET  /api/agent/status              → حالة الـ Agent وآخر تشغيل
```

## أمثلة
- "راجع التقارير الجديدة" → `review-daily-reports` (يتحقق من الحقول الناقصة، التوقيع، عدد الزيارات)
- "لخص يوم أحمد اليوم" → `summarize-day` { repId, date }
- "هل فيه مشاكل ميدانية النهاردة؟" → `field-alerts`

## التوسع المستقبلي (اختياري)
لو أضفت `ANTHROPIC_API_KEY` لاحقاً، يمكن ترقية نفس الـ Skills لتعمل مع LLM، لكن **الوضع الافتراضي يبقى محلي 100%**.
