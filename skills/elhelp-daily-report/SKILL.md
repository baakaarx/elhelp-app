# ElHelp Daily Report — التقرير اليومي

## النموذج مطابق للورقة
- رأس: اسم المهندس، التاريخ، اليوم، وقت الخروج/العودة، الظروف الطارئة
- جدول زيارات (حتى 30): اسم العميل/المزرعة، المحافظة، المركز، القرية، الهاتف، المساحة بالفدان، المحاصيل، التوصيات، نتيجة الزيارة
- ذيل: توقيع إلكتروني (`signedName` + `signedAt`) + ختم "أُرسل عبر الهلب"

## قواعد التحقق (يستخدمها الـ Agent)
1. **الحقول الإلزامية**: `engineerName` ≥2، `reportDate` صحيح وغير مستقبلي، `visits.length` 1..30، كل زيارة لها `customerName`
2. **التوقيع**: `signedName` ≥2، `confirmed === true`، `signedAt` خلال نفس اليوم
3. **الوقت**: `leftAt` و `returnedAt` بصيغة `HH:MM` 24h، و `leftAt <= returnedAt` لو كلاهما موجود
4. **المحتوى**: يحذّر لو "نتيجة الزيارة" أو "التوصيات" فارغة لأكثر من 50% من الزيارات
5. **التكرار**: `id` فريد — إعادة الإرسال آمنة (`INSERT OR IGNORE`)
6. **المدة**: يحتفظ بالتقرير حتى `RETENTION_DAYS` ثم يُحذف تلقائياً

## PDF عربي RTL
- يُبنى بـ `pdfmake` + خط `Noto Naskh Arabic` (400/700)
- معالجة RTL: تقسيم يدوي للأسطر + وصل بـ `\u00A0` (non-breaking space) بدون عكس النص المنطقي
- اتجاه الصفحة: `A4 landscape`، جدول 10 أعمدة معكوسة لوضع "م" على اليمين
- يُحمّل من `GET /api/daily-reports/:id/pdf` مع `Content-Disposition: attachment`

## ما يفعله الـ Agent
- `review-daily-reports`: يراجع كل التقارير `status=new` ويعطي درجة جودة (مكتمل/ناقص/يحتاج متابعة)
- يقترح نص للمدير: "تقرير سارة 2026-11-01: 3 زيارات، توصيات ناقصة في زيارتين — اطلب توضيح"
- لا يغيّر `status` تلقائياً — المدير هو من يعتمد `PATCH ... { status: 'reviewed' }`
